A transcript is not a blob of text

Grep over the raw JSONL treats a shell command, the file it read, the traceback it printed and the sentence you typed as the same kind of evidence. They are not. Every turn is classified once, at parse time, and everything downstream keys off that.

kindpointswhat it is
user_request5something you typed
error4a tool result flagged as an error, or one that opens like a traceback
assistant_text3prose the model wrote
tool_input2a tool call and its arguments, including the file it touched
tool_output1what the tool printed
thinking1extended thinking and Codex reasoning summaries
meta0system reminders and injected commands, excluded unless asked for

The ranking rule, in full

No learned model and no bm25. The score is the sum of four named integers, and the tool will print them next to any result with --explain.

score = kind + terms + phrase + recency

kind from the table above.
terms: 2 points per distinct query term present. Repeats earn nothing, so a log line that screams one word two hundred times cannot outrank a sentence that uses every word once.
phrase: 3 points if every term fits inside one 60 character window.
recency: 3 within a week, 2 within a month, 1 within six months, 0 beyond.

Ties break on newer first, then session, then position, so two runs over the same index return the same order.

Try it

Running against the synthetic fixture archive that the test suite uses: 8 sessions, 31 turns, with known content planted in it. Nothing here comes from a real transcript.

Nothing derived from the archive is committed

The index holds raw transcript text, so it lives outside the repository, under ~/.local/share/session-search, and *.db is gitignored as a second line of defence. Everything on its way to a terminal or a file goes through one redactor. The redactor's output is then audited by a checker written separately, sharing no code and no patterns with it, because a leak check that reuses the filter's own regex inherits the filter's own bug and reports clean.

The audit runs over every turn in the real archive, not a sample: 51,881 turns, 0 findings. It also scans for NUL bytes in Python rather than with grep, because one NUL byte makes a file binary to git grep, which then skips it in silence and reports a clean tree it never read.

What it does not do

Attachment records are not indexed. In this archive they are harness injections rather than conversation: tool listings, skill listings, task reminders. Codex reasoning blobs are not indexed either, because they are encrypted and contain no searchable text. Both counts are printed at index time, so the part you are not searching is visible instead of implied. There is no --no-redact flag, and there will not be one.
